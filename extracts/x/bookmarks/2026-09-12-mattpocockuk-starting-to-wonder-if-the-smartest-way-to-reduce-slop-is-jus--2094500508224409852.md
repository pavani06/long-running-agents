# reduzir código para reduzir slop

**@mattpocockuk** · [2094500508224409852](https://x.com/mattpocockuk/status/2094500508224409852) · `opinion`

## Resumo
Matt Pocock sugere que a forma mais inteligente de combater código 'slop' é simplesmente produzir menos código, tratando redução de código como meta contínua do code review enquanto se mantém a complexidade ciclomática baixa. Menos código significa menos manutenção e menos bugs.

## Pontos-chave
- A principal alavanca contra slop é reduzir o volume de código produzido, não apenas melhorar sua qualidade
- Code review deveria forçar redução contínua de código, mas combinada com complexidade ciclomática baixa (evitar código denso/espaguete como falsa economia)
- Menos código implica menos superfície de manutenção e, consequentemente, menos bugs
